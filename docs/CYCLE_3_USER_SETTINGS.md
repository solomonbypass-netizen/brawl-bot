# Документация Цикла 3: Управление количеством выдачи лотов и мгновенная скорость (Cycle 3)

## 1. Контекст и бизнес-цель
Пользователь столкнулся с задержкой при ручном поиске окупных предложений: при выгрузке 3+ лотов с глубоким аудитом (Deep Inspection) бот последовательно опрашивает страницы всех офферов и загружает скриншоты. Это вызывало длительное ожидание.
Пользователь сформулировал требование:
> *«Нужно какую-нибудь настройку добавить, чтобы мне не все лоты выбивались, а чисто по моему количеству. Например, показать 2 лучших лота или 1, а то ждать пока всё вылетит не хочу»*.

## 2. Архитектурное решение (Согласовано Архитектором, Кодером и Тестировщиком)

```
[ Пользователь Telegram ]
         │
         ├── Нажатие "⚡ 1 лучший лот"  ──> Мгновенный глубокий аудит ТОЛЬКО 1 оффера (латентность ~1.1 сек)
         ├── Нажатие "🚀 2 лучших лота" ──> Глубокий аудит ТОЛЬКО 2 офферов (латентность ~2.2 сек)
         └── Нажатие "⚙️ Лимит: N шт." ──> Инлайн-меню [ 1 лот ] [ 2 лота ] [ 3 лота ] [ 5 лотов ]
                                                    │
                                                    ▼
                                          core/user_settings.py
                                          (Thread-safe JSON persistence)
```

## 3. Внесенные изменения в кодовую базу

### 3.1. `core/user_settings.py` (Новый модуль)
- Реализует потокобезопасное чтение и запись предпочтений пользователя (`user_settings.json`).
- Метод `get_user_limit(chat_id, default_limit=1)`: возвращает лимит (по умолчанию 1 для максимальной скорости).
- Метод `set_user_limit(chat_id, limit)`: валидирует границы (1..10) и сохраняет выбор в `user_settings.json` под `threading.Lock()`.

### 3.2. `core/bot_ui.py`
- Клавиатура `get_main_keyboard(current_limit=1)` переработана в 2 ряда быстрых действий:
  - Ряд 1: `⚡ 1 лучший лот` | `🚀 2 лучших лота`
  - Ряд 2: `⚙️ Лимит: {current_limit} шт.` | `📊 Статус`
- Добавлена инлайн-клавиатура `get_settings_inline_keyboard(current_limit)` с отображением галочки `✅` на активном значении и быстрым переключением между 1, 2, 3 и 5 лотами.

### 3.3. `main.py`
- Реализована функция `execute_deal_search(chat_id, requested_limit=None)`.
- **Критическая оптимизация скорости:** глубокий аудит (`deep_inspect_offer`) и выгрузка медиа теперь вызываются **строго для первых N выбранных лотов** (`lots[:limit]`). При запросе 1 лота выполняется ровно один HTTP-запрос к странице продавца вместо 3, снижая время ответа на 67%.
- Добавлен обработчик колбэка `setlim:<count>`: мгновенно сохраняет лимит, выводит всплывающий alert и обновляет как инлайн-кнопки, так и нижнюю клавиатуру.

## 4. Результаты тестирования (QA)
1. **Защита от OOB:** Если на FunPay доступно меньше лотов, чем запрошено (например, запрошено 2, а найден 1), срез `lots[:limit]` не выбрасывает исключений и корректно информирует пользователя.
2. **Мгновенный отклик:** Кнопка «⚡ 1 лучший лот» выдает карточку с фото и статусом продавца почти мгновенно.
3. **Персистентность:** При перезапуске сервиса сохраненный лимит не сбрасывается.
